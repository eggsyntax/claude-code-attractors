# These are not in a particular order!

01. Claude Code doesn't have a settable temperature parameter. Consider adding variation via prompts or other means.
02. Probably it would be smart to have you or another LLM check the resulting artifacts to ensure that they don't contain code that would harm an unsuspecting user who runs them. That seems unlikely, but we should probably rule it out.
03. Add "collaboration depth" metric if we can operationalize it well.
04. We may want to either a) capture some static files (eg images) from runs of the code written by the agents, for future analysis; or b) encourage the agents to do so. I'd lean somewhat toward a).
05. Consideration for discussion: in one run, the agents were extremely prolific, creating a large number of python files, making analysis more difficult. On the one hand, we could discourage them from doing so; on the other, this might itself provide a kind of influence that we might not want.
06. It seems potentially valuable to try to preserve what the claude code agents are doing, not just their created artifacts and final contribution to the conversation.
    * It's possible that if we capture it all, the resulting filesize would be unwieldy, but we should probably try it and find out.
    * It's possible, for all I know, that one agent might write an artifact and then neither of them ever runs it (or perhaps even looks at it!). So it seems like it would be useful to know whether / when agents view and run the artifacts. 
    * Probably there are other useful things to preserve about what agents are doing during their turn. Thoughts on what?
07. Do we still need the `--sandbox` argument? Let's get rid of it if not.

# Deferred ideas from brainstorming session (2026-01-29)

10. [Maybe] Structured feature vectors per turn (superlative density, code-to-prose ratio,
    question count, concrete vs abstract nouns) as an alternative/complement to embeddings
    for tracking behavioral convergence rather than topical convergence.
11. [Maybe] Try different agent framings to reduce priming effects: "another AI" vs
    "another Claude Code instance" vs just using names with no AI mention.
12. [Maybe] More dynamic turn structure instead of fixed alternation -- variable-length
    contributions, ability to "pass", parallel threads.
13. [Maybe] Baselines: human-human conversations, human-Claude, different model pairings
    (Opus-Opus vs Sonnet-Sonnet vs Opus-Sonnet).
15. [Maybe] Agent asymmetry: give different agents different tool sets to create natural
    division of labor.
16. [Maybe] Memory persistence: let agents read summaries of past runs to see if they
    build on previous work or repeat.
17. [Maybe] Intervention points: ability to inject a message mid-conversation
    ("A human observer asks: why did you choose this direction?").
18. [Maybe] Branching: run the same conversation to turn N, then branch into multiple
    continuations to measure trajectory variance.
19. [Maybe] LLM-as-judge for artifact quality (novelty, correctness, coherence).
    Most expensive but probably most informative complement to structural metrics.
20. [Maybe] Inter-run convergence: measure whether different runs within a runset
    end up in similar semantic regions (beyond just shared topic keywords).
21. [Maybe] Configurable agent personalities via prompt fragments.
22. [Maybe] A/B testing framework for prompt variations.
